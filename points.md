



# Чек-лист этапа 1

Консольная утилита (Java 21, Gradle Groovy DSL, один fat-jar). Она обходит каталог проекта, разбирает исходники в AST и пишет структурированный индекс в один файл SQLite (`index.db`). Индекс затем прикладывают к чату с ИИ-ассистентом. Ассистент выполняет SQL (Python `sqlite3`, без интернета), находит нужные классы, методы, зависимости и читает исходный текст. Поэтому схема и запросы должны быть удобны **для машинного чтения ассистентом**, а не только для человека.

Требования к результату:

- [x] Один самодостаточный файл `.db` (без `-wal`/`-shm` рядом после завершения).
- [x] Целевой размер до 10–20 МБ на ~500 Java-классов; параметр `--no-source` даёт лёгкую версию без текста.
- [x] Идемпотентность: повторный запуск без изменений ничего не меняет в данных.
- [x] Утилита только **читает** проект и ничего в нём не изменяет.

## Чек-лист этапа 2

- [x] Схема из раздела 6.1 и FTS5: все `CREATE` с `IF NOT EXISTS`, плюс служебные индексы.
- [x] `Db`: PRAGMA при открытии, проверка совместимости, завершение (checkpoint, `journal_mode=DELETE`, optimize, `VACUUM`).
- [x] Транзакция на каждый файл, ошибка БД пишется в `index_errors` со стадией `DB` отдельной транзакцией.
- [x] `meta`, `files` (BOM, EOL, `line_count`, `sha256`, `lang`, `kind`), `--no-source`.
- [x] `index_errors` для `SKIP_SIZE`, `SKIP_BINARY` и `READ`.
- [x] Тесты: схема, идемпотентность, FTS, финальное состояние файла.
- [ ] `files.module`: заполнит этап 5.
- [ ] `--incremental`: этап 6.

## Чек-лист этапа 3

- [x] `types` (все пять видов, вложенные, `parent_type_id`, `fqn`, модификаторы, диапазоны с Javadoc, `doc_summary`).
- [x] `members` (METHOD, CONSTRUCTOR, FIELD, ENUM_CONSTANT, RECORD_COMPONENT, INITIALIZER) и сигнатуры.
- [x] `imports`, `annotations` (аргументы срезом исходника), `type_relations` без резолва.
- [x] Синтаксическая ошибка пишется в `index_errors` со стадией `PARSE`, а файл остаётся в `files` и FTS.
- [x] Разбор идёт в пуле (парсер на поток), запись в одном потоке, id детерминированы.
- [ ] `calls`, `type_deps` и `SymbolSolver` будут на этапе 4.

## Чек-лист этапа 4

- [x] `calls`: METHOD, NEW, CONSTRUCTOR_REF, METHOD_REF, с атрибуцией на ближайший член (поля и инициализаторы тоже члены).
- [x] `type_deps`: IMPORT, EXTENDS, IMPLEMENTS, FIELD, PARAM, RETURN, NEW, CALL, ANNOTATION, без дубликатов.
- [x] `SymbolSolver`: JDK + корни `src/main/java` и `src/test/java`, по своему набору на поток, любая ошибка даёт `resolved=0`.
- [x] `--no-resolve`: всё `resolved=0`, но FQN из явных импортов сохраняется.
- [x] `members.signature` в FQN, `callee_signature` в том же формате.
- [ ] Не покрыто: `this(...)` и `super(...)`, вызовы через статические импорты без квалификатора, разрешение к типам из внешних jar (внешние JAR запрещены ТЗ).
