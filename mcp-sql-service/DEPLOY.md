# Развёртывание mcp-sql на сервере

На сервере работают четыре контейнера: `mcp-sql` (сервис), `mcp-sql-bot` (Telegram-бот), `mcp-sql-web` (сайт со статистикой) и `caddy` (HTTPS и маршрутизация). Наружу открыты только порты 80 и 443 у Caddy.

## 1. Подготовка

- Сервер с Docker и плагином Compose (`docker compose version`).
- DNS: запись A для домена указывает на IP сервера.
- Открыты порты 80 и 443 (Caddy выпускает сертификат через порт 80).
- На вашем компьютере: `docker login`, затем публикация образов (раздел 5).

## 2. Файлы на сервере

Создайте каталог, например `/opt/mcp-sql`, и положите в него три файла из `mcp-sql-service/`:

- `docker-compose.yml` (без `docker-compose.local.yml`),
- `Caddyfile`,
- `.env` (из `.env.example`).

В `.env` заполните домен, `MCPSQL_INTERNAL_KEY`, `BOT_TOKEN` и `BOT_PUBLIC_URL`. Секрет для внутреннего ключа:

```bash
openssl rand -hex 32
```

Права на файл: `chmod 600 .env`. Не добавляйте `.env` в git и не отправляйте его в чаты.

## 3. Запуск

```bash
docker compose pull
docker compose up -d
docker compose ps
docker compose logs --tail 50 mcp-sql mcp-sql-bot
```

## 4. Проверка

1. Откройте `https://ВАШ_ДОМЕН/`: должна открыться страница со статистикой.
2. `curl -i https://ВАШ_ДОМЕН/internal/stats` должен вернуть 404 (путь наружу не опубликован).
3. В боте `@mcp_sql_bot` нажмите `/start`, получите ключи, загрузите базу `push`-ом, затем «Мои данные».
4. Вызовите `https://ВАШ_ДОМЕН/mcp/ИМЯ_БАЗЫ` с ключом чтения, например `index_info`.

## 5. Выпуск новой версии

На вашем компьютере:

```powershell
.\scripts\publish.ps1 -Version 0.1.1
```

(Linux и macOS: `scripts/publish.sh 0.1.1`.) Скрипт запускает тесты, собирает три образа под linux/amd64 и публикует их с тегами `0.1.1` и `latest`. Ключи `-SkipTests`, `-NoLatest` и `-NoPush` отключают тесты, тег `latest` и публикацию.

На сервере укажите `MCPSQL_TAG=0.1.1` в `.env` и выполните:

```bash
docker compose pull
docker compose up -d
```

Откат: верните прежний `MCPSQL_TAG` и выполните те же команды. Данные лежат в томе `mcp-data` и при обновлении сохраняются.

## 6. Данные и резервные копии

- Базы пользователей и файл `system/user.db` лежат в томе `mcp-data`. Базы живут не дольше срока ключей (до недели), поэтому полноценные резервные копии обычно не нужны.
- Если `user.db` потерян, пользователям придётся заново получить ключи и загрузить базы. Пока в `user.db` нет ни одного пользователя, чистка по сроку ничего не удаляет.
- Копию `user.db` надёжно делать при остановленном сервисе: `docker compose stop mcp-sql`, затем копия содержимого тома `mcp-data/system`, затем `docker compose start mcp-sql`.

## 7. Безопасность

- `MCPSQL_INTERNAL_KEY` и `BOT_TOKEN` никому не показывайте. Если токен бота утёк, отзовите его в BotFather (`/revoke`), обновите `.env` и перезапустите бот: `docker compose up -d mcp-sql-bot`.
- Ключи пользователей хранятся только в виде хешей, показать их повторно нельзя.
- Если нужно срочно отключить пользователя, закройте доступ сбросом через бота. Блокировка отдельного пользователя пока выполняется вручную: `banned = 1` в таблице `users` файла `user.db`.
- Проверьте, что `docker compose ps` показывает опубликованными только порты Caddy.
